## 🧠 Reflection

### How can I ensure that my code, program, or software is functional and secure?

Ensuring that my code is functional and secure begins with a disciplined approach to validation, testing, and review. Functionality is not just about whether a feature works under ideal conditions; it also requires verifying behavior across edge cases, invalid inputs, and unexpected scenarios. Writing comprehensive JUnit tests helped confirm that each class enforced its constraints consistently and that the service layers maintained data integrity.

Security also depends on careful validation, such as preventing null values, enforcing length limits, and rejecting malformed data. These practices reduce the risk of vulnerabilities and help ensure that software behaves predictably even when faced with incorrect or malicious input.

### How do I interpret user needs and incorporate them into a program?

Interpreting user needs is an essential part of building reliable software. Requirements often begin as high-level descriptions, and it is the developer's responsibility to translate those descriptions into concrete behaviors, constraints, and testable conditions.

In Project One, each requirement—such as ID length limits, phone number formats, or date restrictions—represented a user expectation about how the system should behave. By turning those expectations into explicit validation rules and corresponding tests, I ensured that the final implementation aligned with what the user actually needed. Testing became a way to confirm not only correctness but also adherence to the intended user experience.

### How do I approach designing software?

When approaching software design, I have learned to think in terms of clarity, modularity, and maintainability. Designing features such as Contact, Task, and Appointment services throughout the course required me to separate responsibilities between model classes and service classes, which made the code easier to test and easier to extend.

Writing tests early in the process also influenced my design decisions because it encouraged me to create methods that were predictable, focused, and easy to validate. This approach aligns with modern development practices, where testing and design support each other to create software that is both robust and adaptable.

By combining thoughtful design with disciplined testing, I can build programs that meet user needs, remain secure, and continue to function reliably as they evolve.
